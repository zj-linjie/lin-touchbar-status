# 口播稿：《我把 Mac 触控条改成了 AI 编程状态灯》（7 分钟版）

**口径说明**

- 目标时长 7 分钟，正文按每分钟约 240～250 字的口播语速估算，全文约 1700 字。
- 只有正文段落需要念出来；每节开头的「画面：」和文中【】里的是给剪辑的提示，不念。
- 各节时长是参考值，实际以录制约 7 分钟为准；单节超时优先砍第 3、4 节里的举例，不要砍开头和结尾。

## 0. 开场（00:00 – 00:35，约 145 字）

画面：先空镜 Touch Bar 实拍——「我想想…」闪烁；快切改文件、授权、宠物走路的特写；最后落到标题。

大家好。先看一眼我 MacBook 顶上这条 Touch Bar。现在它显示「我想想」，意思是我的 AI 助手正在思考；我让它改代码，它会实时报出这一次加了几行、删了几行；任务跑完，旁边那只小宠物还会朝我挥挥手。这条触控条，现在是我桌面上最没用、但又最上瘾的一块屏。今天用七分钟，讲讲我怎么用一堆小脚本，把它变成 AI 编程智能体的实时状态灯。

## 1. 痛点：派完活之后的煎熬（00:35 – 01:40，约 230 字）

画面：录屏演示——给 agent 发任务后切走干别的，回来发现它卡在授权；再切到额度页面展示「要专门打开 app 才能看用量」。

先说为什么要做这个东西。现在写代码的方式，基本变成了：给 agent 派个活，然后等。但等的过程特别煎熬——它到底是在思考，还是在跑命令？是改文件改到一半，还是已经卡住了？更烦的是授权：agent 干到一半停下来等你点头，而你根本不知道，一刷手机回来，发现它原地罚站了十分钟。还有额度：套餐用了多少、什么时候重置，得专门打开 app 才能看。这些都属于「不盯不行、盯着又没用」的信息，最合适的归宿，其实就是屏幕上永远亮着的那一小条。所以我的目标很简单：不切窗口、不打开任何 app，余光一扫，就知道 agent 的状态。

## 2. 方案总览：三层胶水（01:40 – 02:45，约 245 字）

画面：一张三格示意图——agent hooks → 状态文件 → MTMR 渲染；每个箭头出现时切对应的代码文件特写。

方案其实特别朴素，一共三层。第一层，agent 本身。Codex 和 ZCode 都支持生命周期 hooks，每发生一个事件——收到提示词、开始用工具、工具跑完、请求授权、任务结束——就把一行 JSON 喂给一个我写的小脚本。第二层，这个小脚本只干一件事：把当前状态原子地写进一个 JSON 状态文件，几十毫秒就退出，不留任何常驻进程。第三层，Touch Bar 侧用了一个免费开源的工具叫 MTMR，它支持一种 shell script 小组件，每一两秒调一次我的读取脚本，读状态文件，渲染成文字、图标和颜色。hooks 负责「发生的时候记一笔」，MTMR 负责「每一秒看一眼」，中间靠一个状态文件解耦。整个项目没有一行 Swift，没有 Xcode，全是 Node 脚本，加起来不到两千行。

## 3. 状态灯：Touch Bar 上到底显示什么（02:45 – 04:05，约 355 字）

画面：逐个切 assets/readme/ 里的真实 Touch Bar 截图——摸鱼中、我想想、跑个命令、改文件行数、等你点头；多槽位拼装时给 items.json 一瞥。

重点来了：状态灯到底长什么样。空闲的时候，它显示「摸鱼中」，还挺诚实的。你一发消息，它变成「我想想」，后面点数会动，旁边挂着计时器，能看到这一回合跑了多少秒。agent 开始跑命令，主状态切到「跑个命令」，配一个终端图标；开始改文件的时候最有意思——它会解析补丁文本，实时跳动新增和删除的行数：单文件显示「read.mjs 加三减零」，多文件显示「三个文件，加二十四，减六」，绿的是加、红的是删。需要授权的时候，整条变成紫色，显示「等你点头」。这里我做了个防呆：授权态最多保留九十秒，如果你拒绝了、取消了，或者 agent 没有后续动作，它会自己回到空闲，不会永远卡在「等你点头」。所有信息还拆成了独立槽位：主状态、计时、工具名、增删行数、当前文件，想怎么拼就怎么拼，没内容的槽位自动留白。另外说下隐私：状态文件里只有事件、工作目录、模型、工具名和时间戳，你的提示词和 agent 的回复，一概不落盘。

## 4. 额度槽位：从逆向接口到滚动窗口（04:05 – 05:20，约 320 字）

画面：Touch Bar 额度槽特写「额度5h余60%-刷新:01:03-周余76%」；切 docs/zcode-usage-api.md 的接口表格；重置时间字段缺失那一下给个标注动画。

第二个大件是额度槽位，显示格式长这样：「额度 5 小时余 60%，刷新 01:03，本周余 76%」。Codex 这边简单，它本地有个 app-server，带一个只读的额度接口，每五分钟查一次就行。ZCode 这边就麻烦了，官方没有开放接口，我把桌面端「用量」页背后的 monitor 接口抓了出来，发现它就是个普通的 HTTP GET，拿个人套餐的 API key 就能调。里面有两个窗口：一个 5 小时滚动窗口，一个每周窗口。这里有个坑：「重置时间」这个字段，只有窗口里有消耗才返回——你额度一点没用，它压根不给。但 Touch Bar 上又不能留空，所以我做了个「锚定」策略：第一次观察到的时候，拿这个时刻加五小时当占位锚点，一直稳定显示，过期了再重新锚。顺手踩的坑也都记在 docs 里了：API key 从配置里运行时读取，绝不写进代码、绝不提交；查询失败就带上波浪号，回退显示上一次的旧值；窗口时长的编码官方没文档，是我从数据里推出来的。

## 5. 宠物彩蛋：从安装包里抠出来的同事（05:20 – 06:00，约 165 字）

画面：宠物帧动画连播——idle 散步、running 奔跑、waiting 干着急、error 摔倒、OK 挥手；再切 deepseek 宠物换装对比。

然后是我最爱的彩蛋：宠物。Codex 的安装包里，其实藏着官方的宠物素材，spritesheet 格式。我写了两个小脚本：一个把素材从 app 包里抽出来，一个把大图裁成 Touch Bar 能用的十几像素小帧。然后每 0.7 秒，根据当前状态选一帧：空闲就在原地散步，思考就撒腿跑，等你授权就原地干着急，出错会摔个跟头，干完了朝你挥手。后来我又加了 deepseek 宠物——通过环境变量一换，同一套状态映射，换个物种继续上班。

## 6. 架构小得意：双 agent 并存（06:00 – 06:35，约 120 字）

画面：并排展示两个状态文件路径；15 行桥接脚本全文上屏（就 15 行，放得下）。

最后说个架构上的小得意。Codex 和 ZCode 的 hooks 协议几乎一样，都是往 stdin 喂一行 JSON。所以接 ZCode 的时候，我没有复制粘贴六百行，而是写了个十五行的桥接脚本：设一个环境变量，把状态文件重定向到另一个路径，然后动态 import 原来的状态机。于是两套 agent 各写各的状态文件，互不干扰，Touch Bar 上想看谁就看谁。

## 7. 结尾：给你的 Touch Bar 也装一个（06:35 – 07:00，约 130 字）

画面：快速回放全片高光三连；落 GitHub 仓库地址 + README quick start 四步；宠物挥手定格收尾。

总结一下：hooks 记状态，MTMR 每秒读，一个 JSON 文件当胶水，再加一只会挥手的宠物。这个项目我已经开源了，README 里有完整的 quick start：装个 MTMR，跑一下安装器，trust 一组 hooks，十分钟就能给你的 Touch Bar 装上这个工作搭子。如果你也天天和 agent 一起写代码，不妨试试——毕竟，让它替你摸鱼之前，你至少得知道它有没有在摸鱼。我们下期见。
